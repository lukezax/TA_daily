# 智兔 API 缓存预热方案（待实施）

## 背景

免费 token 每天 198 次 × 4 个 = 792 次/天。周末/节假日不跑 pipeline 时这些额度浪费了。

## 方案：非交易日预热缓存

利用周五晚、周六晚的闲置额度提前拉取日K数据，周日晚正式执行时大部分数据已在缓存中。

## 流程

```
每天 21:00 触发
    ↓
明天是交易日？
    ├── 是 → 正常执行 pipeline
    │        检查预热结果 → 已预热的股票信任缓存（跳过过期检查）
    │
    └── 否 → 距离下一个交易日 ≤ 3天？
              ├── 是 → 执行缓存预热（只拉日K，不分析）
              └── 否 → 跳过
```

## 预热逻辑

1. 获取股票列表 → 排除创业板/科创板/ST → ~3000只
2. 读取已有预热结果（前一天的累计）
3. 从未预热的股票中取前 792 只，拉取日K保存到本地
4. 记录预热状态到 `reports/.preheat_status.json`

## 预热状态文件格式

```json
{
  "date": "2026-05-16",
  "target_trading_day": "2026-05-19",
  "total_completed": 1530,
  "this_batch_success": 780,
  "this_batch_failed": 12,
  "completed_codes": ["000001.SZ", "000002.SZ", ...],
  "failed_codes": ["000xxx.SZ", ...]
}
```

## 正式执行时的处理

周日晚正式执行时：
1. 读取 `.preheat_status.json`
2. 检查 `target_trading_day` 是否匹配明天
3. 匹配 → 对 `completed_codes` 中的股票，`get_stock_history_data` 信任缓存（不检查过期）
4. 不匹配或文件不存在 → 忽略预热，正常全量执行

## 缓存有效性

- 周五收盘后数据不会变 → 周五/周六拉的日K到周日晚仍然是最新的
- 但 `_is_expired` 的 18:00 分界线逻辑会认为超过 24 小时的数据过期
- 解决：对预热过的股票传 `trust_cache=True`，跳过过期检查

## 节假日处理

- 触发条件："距离下一个交易日 ≤ 3天"
- 长假（如5天）：只有最后2-3天会预热，前面的天跳过
- 预热数据如果到正式执行时已超过 72 小时 → 自然过期，正常重新拉取（不会出错）

## 涉及修改的文件

| 文件 | 改动 |
|------|------|
| `pipeline/orchestrator.py` | `_run_pipeline` 增加预热分支；新增 `_run_preheat()`、`_load_preheat_result()` |
| `stock_filter.py` | `run_filter()` 接收 `preheat_codes` 参数 |
| `api.py` | `get_stock_history_data` 新增 `trust_cache` 参数 |

| 场景 | 无预热 | 有预热 |
|------|--------|--------|

| 免费token是否够用 | 不够（需付费token兜底） | 基本够用 |
