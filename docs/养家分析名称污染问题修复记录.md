**2026-08-10 日报**（`reports/2026-08-10.html` 第15709行）：600285.SH（羚锐制药）卡片下的「养家视角分析」标题被写成：

正文数据（价格 ¥22.24、PE 12.8、60日高点 23.65、医药基本面）全部是羚锐制药的真实数据——**只有名称错，数据没错**。

## 二、根因链（5 层）

```
① 数据层    pipeline/analysis_client.py _process_batch():
            提交 payload 只有 symbols:["600285"]，不带股票名称
            ↓
② 状态层    AgentState 只有 company_of_interest(代码)，无 company_name 字段
            （后端 simple_analysis_service.py 已用 _resolve_stock_name()
             解析出"羚锐制药"并存入 task 文档，但只用于显示，从未传入 graph）
            ↓
③ 提示层    yangjia_analyst.py user prompt 只有"股票 600285.SH 的真实市场数据"
            （trade_date 也取了但从未注入 prompt，导致 08-10 报告中出现
             "2026-08-07" 的错误日期）
            ↓
④ 锚点污染  system prompt = chaoguyangjia-perspective/SKILL.md 全文，
            其中龙虎榜案例含具体股票名（沪硅产业×2、绿的谐波×2、值得买、
            长电科技）→ 这是系统提示里仅有的 A 股股票名
            ↓
⑤ 模型弱    养家跑在 quick_think_llm = local（本地小模型，localai:8080），
            被迫自拟名称 → 锚点"沪硅产业"被套到 603296/601211/002289/603186；
            600285 凭训练记忆猜成"上海电气"(601727)
            ↓
⑥ 渲染层    pipeline/report_generator.py 的 _md_to_html 原样输出 LLM 标题，零校验
```

**一句话根因**：正确名称在数据源里存在（卡片名、后端 task 文档都是对的），但整条链路从未把名称传给养家 LLM；而 prompt 里唯一的股票名锚点"沪硅产业"诱导了小模型。

**两类错误要区分**：
- **锚点污染类**（→沪硅产业/绿的谐波/值得买/长电科技）：SKILL.md 案例名被套用 → 本次 SKILL.md 净化已根治
- **记忆幻觉类**（→上海电气/华峰超纤/中信证券）：小模型训练知识记错代码-名称映射 → SKILL.md 净化无效，需方案A/C

## 四、待实施方案（观察后决定）

### 方案A｜养家分析师内部补名（单文件，治本）
- 位置：`TradingAgents-CN/tradingagents/agents/analysts/yangjia_analyst.py`
- 做法：复用已有 stock_data 搜索路径读 `stock_data/stock_list_all.json`（600285→羚锐制药 正确），prompt 改为"股票 600285.SH（羚锐制药）的真实市场数据"，并指示"标题只写代码、禁止自拟名称；SKILL.md 里的股票名均与当前标的无关"；同时把 `trade_date` 注入 prompt（顺带修复错误日期问题）
- 优点：单文件、不动 API 契约、立即生效
- 依赖：stock_list_all.json 质量（该文件本身有零星错误：600641→"先导基电"实为万业企业）

### 方案B｜后端把 stock_name 传进 graph state（多文件，最可靠）
- 位置：`simple_analysis_service.py`（启动 graph 时传名）+ `agent_states.py`（新增 company_name 字段）+ `yangjia_analyst.py`（读 state）
- 优点：名称来自 `_resolve_stock_name()` 权威数据源，惠及所有分析师
- 成本：动 3-4 个文件 + graph 初始状态，需回归测试

### 方案C｜渲染层校验（单文件，保险丝）
- 位置：`pipeline/report_generator.py`
- 做法：渲染养家报告前检测标题内"6位代码（名称）"与卡片名不符时重写为 `{代码} 养家视角分析`；历史报告可写一次性脚本批量修复
- 优点：不改分析链路、可回溯修复历史 HTML
- 局限：只修显示，正文内错误名称会漏（目前正文无此问题）

### 方案D｜数据治理（长期）
- `stock_list_all.json` 数据源校准（600641 错误条目）
- `pipeline/filter_runner.py` 第95行自选股入库 `name=code` 导致 603296 等卡片无名称 → 改为从股票列表查名补全

**推荐组合**：A + C（治本 + 保险），B 作后续增强，D 择机做。

## 五、观察与验证方法

### 每日检查（报告生成后）
```bash
# 1. 检查养家标题里的名称是否与卡片名一致（重点看括号名称）
#    预期：不再出现"沪硅产业/绿的谐波/值得买/长电科技/上海电气"等错误名称
grep -o '养家[^<]*' reports/2026-*.html | grep '（' | grep -v '个股\|框架\|分析报告'
```

### 判定标准
- **生效信号**：连续 5 个交易日，养家标题不再出现括号内错误名称（锚点类应立即消失；记忆幻觉类仍有概率，属预期，需方案A/C 才根治）

- **关注点**：600285 是重点观察标的（本次事故对象）

### 观察窗口
建议观察 **2-4 周**（覆盖不同市场情绪阶段），再决定是否实施方案A/C。
